# 能源抢夺战（Core Heist）玩法与开发规格书

[English](../../en/development/core-heist-design.md) · **简体中文** · [繁體中文](../../zh-TW/development/core-heist-design.md)

本规格书定义第一款基于 `mpm-core` 与 `team-party` 的纯组队协作对抗自研小游戏模组 **`core-heist`（能源抢夺战）** 的完整玩法规则、场地结构、联机同步、AI 行为与开发里程碑，并作为后续实现的唯一设计基准。

## 1. 模组定位与准入声明

- **模组 ID**：`core-heist`（分类：`game`）
- **依赖模组**：`requires: ["mpm-core", "team-party"]`（必须同时在 [catalog/mods.json](../../../catalog/mods.json) 与 `mod.json` 声明）
- **槽位注册**：使用 `mpm-core` 的 `register_minigame()` 动态槽位（`>= 1000`），遵循[自研模组开发规范](mod-development.md)与[协作对抗小游戏准入门槛规范](coop-minigame-gating.md)。
- **准入门槛声明（纯组队限定 `"team_only"`）**：

```gdscript
"admission": {
	"mode_support": "team_only",
	"min_teams": 2,
	"max_teams": 4,
	"min_total_players": 2,
	"min_players_per_team": 1,
	"allow_local_couch": false,
}
```

- **门槛行为**：
  - 未开启 `team-party`（FFA）或本地同屏模式时，大厅左侧列表自动灰化锁定（显示 `[需组队]` / `[仅联机]`），且不进入默认模式、街机模式或 15 格 CRT 转盘。
  - 允许房主以“1v1”或“1v2”等不对称人数开局；当某队仅有 1 名成员（含掉线后降为 1 人）时，下方的双人共振核心会自动触发单人轻量化保底。

## 2. 核心玩法循环与 75 秒节奏

对局采用**服务器权威（Host-Authoritative）**，总计 **3 秒准备 + 75 秒正式对抗**：

1. **准备阶段（3 秒）**：
   - 各队在所属队色回收炉前成列出生，镜头带过中央熔炉产线与各队回收炉位置，HUD 显示队伍颜色与目标提示。
2. **第一阶段：标准产线（0–45 秒）**：
   - 中央能源塔与双向短传送带持续吐出**标准电池（+1 分，轻量，1.0× 移速）**与**黄金高压电池（+3 分，中量，0.88× 移速）**。
   - 玩家搬运回自家回收炉即刻计分并锁定 3 秒；也可直接冲进领先敌队基地偷出未锁定的电池。
3. **第二阶段：重型反应炉核心降临（45–60 秒）**：
   - 第 45 秒响起工业警报并在场心投射落地光柱，2 秒预警后空投**重型反应炉核心（+5 分）**。
   - **单人搬运**：移速降至 `0.55×`，且受敌方推搡易掉落。
   - **双人电磁共振（团队核心协作）**：当持核玩家的**同队队友**进入 `2.6m` 范围内，双方脚底出现队色电磁共振光束，移速提升至 **`1.15×`** 并获得高抗击退（被轻推不掉核）。
   - **单人队保底**：若该队当下仅剩 1 名存活成员（如单人组队或队友掉线），单人搬运速度自动调轻为 `0.85×`，避免卡关。
4. **第三阶段：过载冲刺（60–75 秒）**：
   - 中央产线速度加倍，第 62 秒再空投第二颗重型核心。
   - 此阶段凡是从敌队回收炉**偷取并成功缴回自家回收炉**的电池，额外获得 **`+1` 偷家红利分**。
5. **结算与同步计分**：
   - 75 秒倒数结束（或场上仅剩 1 支有效队伍仍有在线成员）时结算。
   - 队伍实时总分＝炉内现存电池总分＋偷家红利；最终通过 `team-party` 的 Squads 同步计分回写房间总榜。

## 3. 操作、搬运、投掷、推搡与偷家规则

延续 Machine Party 纯键盘极简操作：

| 输入 | 空手状态 | 持电池／核心状态 |
| --- | --- | --- |
| `WASD` / 方向键 | 移动与转向（靠近地面或未锁定炉内电池自动拾取） | 移动与转向（依电池重量套用移速倍率） |
| `Space` | **工业推搡**：前方扇形推击，命中敌队造成 `0.45s` 硬直跌倒并震落其手中电池；对同队队友**零伤害／零推开**（经 `team_support.are_teammates` 过滤） | **向前抛投／传递**：朝面向方向抛出 `2.5m`（可远距离投入自家回收炉，或抛给前方队友接力） |

### 回收炉金库规则
- **存入磁吸锁定**：标准（+1）与黄金（+3）电池存入自家回收炉后，进入 **`3.0 秒` 磁吸保护锁**（外圈显示蓝／队色护盾环），期间敌队无法偷取；锁定解除后敌队可进入范围自动偷走（每次优先偷最高分且已解锁的电池）。
- **重型反应炉核心永久锁定**：+5 分重型核心一旦成功送入回收炉即**永久锁死**，无法被偷走，确保双人冒险抢核的成果不可逆。

## 4. 场地布局与 2–4 队动态缩放

- **场地尺寸**：依有效队数动态缩放，2 队（`2v2`、`4v4`）为 `24m × 24m`、3–4 队（`2v2v2`、`2v2v2v2`）为 `28m × 28m`，坐落于深炭灰工业底台并设四周护栏防止跌落卡死。
- **对称基地配置**：
  - **2 队**：对角线两端（西南 vs. 东北），支持每队最多 4 人无重叠出生站位（`4v4`）。
  - **3 队**：正三角形三顶点（120° 等距）。
  - **4 队**：正方形四角落。
- **场内动线与工业厂房背景**：
  - 中央为高台“反应炉喷口”与左右两条短传送带（分流产出电池），配合 4 根中场缓冲柱绕行遮挡。
  - 场地北侧建有完整厂房背景墙、横向管线、暖色荧光灯管以及一块大型 **3D 叙事工业 CRT 监视器**，以磷光绿 `Terminal F4` 实时显示 `MM:SS` 倒计时与阶段状态（`STANDARD LINE` / `HEAVY CORE` / `OVERDRIVE`）。
- **官方质感光照、后处理与叙事优先 HUD**：
  - 采用低饱和暖调工业车间光照，并通过 `BackBufferCopy` 复用官方 `vignette.gdshader` 与 `posterization.gdshader` 后处理。
  - 移除蓝色圆角悬浮条：仅保留左上角无框队色描边比分（右上角完全让给 `team-party` HUD）、开局准备与前 `2.5s` 追踪本地玩家的 `YOU` 方括号定位标、居中大号描边 `3-2-1-GO!` 倒数、底部 0 圆角 CRT 共振提示条，以及仅单机预览显示的 0 圆角磷光绿 CRT 结算框（官方联机局交由原版计分板接管）。
- **基地可视化**：每座回收炉上方悬挂队色大型点阵计分牌，炉内实体格位随存入电池数量亮起并摆放对应模型。
- **8 人多队电池容量缩放**：地面标准电池上限（`10`→`18`）、黄金电池上限（`3`→`6`）及产线节奏随队数与人数动态缩放，并恒定预留 2 个对象池槽位给重型核心。

## 5. 联机权威与状态同步

- **房主权威模拟（`multiplayer.is_server()`）**：
  - 所有电池生成、拾取归属、抛投轨迹、推搡跌倒、3 秒锁定计时、共振判定与分数加减均由房主统一计算。
- **输入与快照 RPC**：
  - 客机上行：`move_dir: Vector2` 与 `action_pressed: bool`（沿用 `spike-ring` / `bubble-blitz` 的轻量输入 RPC 模式）。
  - 房主下行：约 `20 Hz` 广播精简快照，包含玩家位置／朝向／硬直／手持电池索引、对象池内各电池状态（`loose` / `carried` / `deposited` / `locked` + 坐标）、共振连线队友对、以及各队实时分数。

## 6. `lobby-bots` AI 控制器设计（`ai_controller.gd`）

每个机器人依当前局势动态切换 4 种微状态，确保 2–4 队混编机器人时也能打出“协作与偷家”效果：

1. **护航手（Co-op Escort）**：检测到同队队友正在搬运 `+5` 重型核心时，优先贴近至 `2.0m` 内维持电磁共振加速，并对靠近 `2.5m` 内的敌队成员发动推搡拦截。
2. **搬运手（Carrier）**：持电池时朝自家回收炉移动，进入 `2.2m` 内直接按 `Space` 抛入炉中；若前方有敌人堵门则先小幅绕柱。
3. **采集／抄家手（Collector / Raider）**：空手时依权重抢夺目标——未锁定重型核心 > 中央黄金电池 > 领先队伍回收炉内已解锁的高分电池 > 标准电池。
4. **守门拦截手（Defender）**：当检测到敌人带着电池从自家回收炉方向逃离且距离 `< 4.5m` 时，优先追击推搡将电池震落并就地回收。

## 7. 模组文件结构与性能红线

```text
mods/core-heist/
├── mod.json                 # id: "core-heist", requires: ["mpm-core", "team-party"]
├── main.gd                  # _mod_init / _mod_ready、注册 admission 与场景替换
├── config.gd                # 平衡常数、颜色、阶段时间、分数权重
├── official_minigame.gd     # 对接原版 Minigame 信号接口
├── core_heist_game.gd       # 服务器权威主逻辑、电池对象池、共振与计分
├── arena_meshes.gd          # 动态 2–4 队场地、传送带、回收炉与柱体网格构建
├── ai_controller.gd         # lobby-bots 协作与抄家 AI
├── fx_pool.gd               # 基于 mpm-core.create_fx_pool() 的特效／火花／共振池
├── hud_ui.gd                # 叙事优先 HUD：左上无框比分、YOU 定位标、大号倒数与 CRT 共振条
├── team_support.gd          # 复制自 mods/_shared/team-support/team_support.gd
├── self_test.gd             # --self-test 无头逻辑验证
└── README.md                # 模组说明文档
```

### 性能与契约红线（对齐[自研模组开发规范](mod-development.md)）
- **零运行时分配**：开局预建最多 **32 颗电池节点池**与共享材质／网格；所有火花、空投光柱、推搡冲击与共振特效均通过 `mpm-core.create_fx_pool()` 预先配置并在开局倒数时在视锥内预热。
- **热路径禁令**：`_process` / `_physics_process` 禁止调用 `get_property_list()`、禁止新建 `Mesh` / `StandardMaterial3D` 或 `queue_free()`。
- **无头与 Lint 规范**：通过 `node scripts/mod-lint.mjs`、不可对 `call()` / `get()` / `get_meta()` 使用无类型 `:=`。

| 里程碑 | 交付项目 | 验收标准 |

| **M1：骨架与动态场地** | `mod.json`、`main.gd`、`config.gd`、`arena_meshes.gd`、注册 `"team_only"` admission | 通过 `mpm-core` 准入检查（FFA 锁定、Team Party 2–4 队正常显示）；2/3/4 队场地网格无重叠 |

| **M3：联机同步、HUD 与 AI** | 20 Hz 快照同步、`hud_ui.gd`、`ai_controller.gd`、`fx_pool.gd` | 机器人能主动贴近持核队友触发共振并进敌区偷电池；60 FPS 压测无节点泄漏 |
