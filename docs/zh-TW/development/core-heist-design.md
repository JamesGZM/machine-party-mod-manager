# 能源搶奪戰（Core Heist）玩法與開發規格書

[English](../../en/development/core-heist-design.md) · [简体中文](../../zh-CN/development/core-heist-design.md) · **繁體中文**

本規格書定義第一款基於 `mpm-core` 與 `team-party` 的純組隊協作對抗自研小遊戲模組 **`core-heist`（能源搶奪戰）** 的完整玩法規則、場地結構、連線同步、AI 行為與開發里程碑，並作為後續實作的唯一設計基準。

## 1. 模組定位與准入宣告

- **模組 ID**：`core-heist`（分類：`game`）
- **相依模組**：`requires: ["mpm-core", "team-party"]`（必須同時於 [catalog/mods.json](../../../catalog/mods.json) 與 `mod.json` 宣告）
- **槽位註冊**：使用 `mpm-core` 的 `register_minigame()` 動態槽位（`>= 1000`），依循[自研模組開發規範](mod-development.md)與[協作對抗小遊戲准入門檻規範](coop-minigame-gating.md)。
- **准入門檻宣告（純組隊限定 `"team_only"`）**：

```gdscript
"admission": {
	"mode_support": "team_only",
	"min_teams": 2,
	"max_teams": 4,
	"min_total_players": 2,
	"min_players_per_team": 1,
	"allow_local_couch": false,
}
```

- **門檻行為**：
  - 未開啟 `team-party`（FFA）或本地同屏模式時，大廳左側清單自動灰化鎖定（顯示 `[需組隊]` / `[僅連線]`），且不進入預設模式、街機模式或 15 格 CRT 轉盤。
  - 允許房主以「1v1」或「1v2」等不對稱人數開局；當某隊僅有 1 名成員（含斷線後降為 1 人）時，下方的雙人共振核心會自動觸發單人輕量化保底。

## 2. 核心玩法循環與 75 秒節奏

對局採**伺服器權威（Host-Authoritative）**，總計 **3 秒準備 + 75 秒正式對抗**：

1. **準備階段（3 秒）**：
   - 各隊於所屬隊色回收爐前成列出生，鏡頭帶過中央熔爐產線與各隊回收爐位置，HUD 顯示隊伍顏色與目標提示。
2. **第一階段：標準產線（0–45 秒）**：
   - 中央能源塔與雙向短傳送帶持續吐出**標準電池（+1 分，輕量，1.0× 移速）**與**黃金高壓電池（+3 分，中量，0.88× 移速）**。
   - 玩家搬運回自家回收爐即刻計分並鎖定 3 秒；也可直接衝進領先敵隊基地偷出未鎖定的電池。
3. **第二階段：重型反應爐核心降臨（45–60 秒）**：
   - 第 45 秒響起工業警報並於場心投射落地光柱，2 秒預警後空投**重型反應爐核心（+5 分）**。
   - **單人搬運**：移速降至 `0.55×`，且受敵方推搡易掉落。
   - **雙人電磁共振（團隊核心協作）**：當持核玩家的**同隊隊友**進入 `2.6m` 範圍內，雙方腳底出現隊色電磁共振光束，移速提升至 **`1.15×`** 並獲得高抗擊退（被輕推不掉核）。
   - **單人隊保底**：若該隊當下僅剩 1 名存活成員（如單人組隊或隊友斷線），單人搬運速度自動調輕為 `0.85×`，避免卡關。
4. **第三階段：過載衝刺（60–75 秒）**：
   - 中央產線速度加倍，第 62 秒再空投第二顆重型核心。
   - 此階段凡是從敵隊回收爐**偷取並成功繳回自家回收爐**的電池，額外獲得 **`+1` 偷家紅利分**。
5. **結算與同步計分**：
   - 75 秒倒數結束（或場上僅剩 1 支有效隊伍仍有在線成員）時結算。
   - 隊伍即時總分＝爐內現存電池總分＋偷家紅利；最終透過 `team-party` 的 Squads 同步計分回寫房間總榜。

## 3. 操作、搬運、投擲、推搡與偷家規則

延續 Machine Party 純鍵盤極簡操作：

| 輸入 | 空手狀態 | 持電池／核心狀態 |
| --- | --- | --- |
| `WASD` / 方向鍵 | 移動與轉向（靠近地面或未鎖定爐內電池自動拾取） | 移動與轉向（依電池重量套用移速倍率） |
| `Space` | **工業推搡**：前方扇形推擊，命中敵隊造成 `0.45s` 硬直跌倒並震落其手中電池；對同隊隊友**零傷害／零推開**（經 `team_support.are_teammates` 過濾） | **向前拋投／傳遞**：朝面向方向拋出 `2.5m`（可遠距離投入自家回收爐，或拋給前方隊友接力） |

### 回收爐金庫規則
- **存入磁吸鎖定**：標準（+1）與黃金（+3）電池存入自家回收爐後，進入 **`3.0 秒` 磁吸保護鎖**（外圈顯示藍／隊色護盾環），期間敵隊無法偷取；鎖定解除後敵隊可進入範圍自動偷走（每次優先偷最高分且已解鎖的電池）。
- **重型反應爐核心永久鎖定**：+5 分重型核心一旦成功送入回收爐即**永久鎖死**，無法被偷走，確保雙人冒險搶核的成果不可逆。

## 4. 場地佈局與 2–4 隊動態縮放

- **場地尺寸**：依有效隊數動態縮放，2 隊（`2v2`、`4v4`）為 `24m × 24m`、3–4 隊（`2v2v2`、`2v2v2v2`）為 `28m × 28m`，坐落於深炭灰工業底台並設四周護欄防止跌落卡死。
- **對稱基地配置**：
  - **2 隊**：對角線兩端（西南 vs. 東北），支援每隊最多 4 人無重疊出生站位（`4v4`）。
  - **3 隊**：正三角形三頂點（120° 等距）。
  - **4 隊**：正方形四角落。
- **場內動線與工業廠房背景**：
  - 中央為高台「反應爐噴口」與左右兩條短傳送帶（分流產出電池），配合 4 根中場緩衝柱繞行遮擋。
  - 場地北側建有完整廠房背景牆、橫向管線、暖色螢光燈管以及一塊大型 **3D 敘事工業 CRT 監視器**，以磷光綠 `Terminal F4` 即時顯示 `MM:SS` 倒數計時與階段狀態（`STANDARD LINE` / `HEAVY CORE` / `OVERDRIVE`）。
- **官方質感光照、後處理與敘事優先 HUD**：
  - 採用低飽和暖調工業車間光照，並透過 `BackBufferCopy` 複用官方 `vignette.gdshader` 與 `posterization.gdshader` 後處理。
  - 移除藍色圓角懸浮條：僅保留左上角無框隊色描邊比分（右上角完全讓給 `team-party` HUD）、開局準備與前 `2.5s` 追蹤本地玩家的 `YOU` 方括號定位標、置中大號描邊 `3-2-1-GO!` 倒數、底部 0 圓角 CRT 共振提示條，以及僅單機預覽顯示的 0 圓角磷光綠 CRT 結算框（官方連線局交由原版計分板接管）。
- **基地視覺化**：每座回收爐上方懸掛隊色大型點陣計分牌，爐內實體格位隨存入電池數量亮起並擺放對應模型。
- **8 人多隊電池容量縮放**：地面標準電池上限（`10`→`18`）、黃金電池上限（`3`→`6`）及產線節奏隨隊數與人數動態縮放，並恆定預留 2 個物件池槽位給重型核心。

## 5. 連線權威與狀態同步

- **房主權威模擬（`multiplayer.is_server()`）**：
  - 所有電池生成、拾取歸屬、拋投軌跡、推搡跌倒、3 秒鎖定計時、共振判定與分數加減均由房主統一計算。
- **輸入與快照 RPC**：
  - 客機上行：`move_dir: Vector2` 與 `action_pressed: bool`（沿用 `spike-ring` / `bubble-blitz` 的輕量輸入 RPC 模式）。
  - 房主下行：約 `20 Hz` 廣播精簡快照，包含玩家位置／朝向／硬直／手持電池索引、物件池內各電池狀態（`loose` / `carried` / `deposited` / `locked` + 座標）、共振連線隊友對、以及各隊即時分數。

## 6. `lobby-bots` AI 控制器設計（`ai_controller.gd`）

每個機器人依當前局勢動態切換 4 種微狀態，確保 2–4 隊混編機器人時也能打出「協作與偷家」效果：

1. **護航手（Co-op Escort）**：偵測到同隊隊友正在搬運 `+5` 重型核心時，優先貼近至 `2.0m` 內維持電磁共振加速，並對靠近 `2.5m` 內的敵隊成員發動推搡攔截。
2. **搬運手（Carrier）**：持電池時朝自家回收爐移動，進入 `2.2m` 內直接按 `Space` 拋入爐中；若前方有敵人堵門則先小幅繞柱。
3. **採集／抄家手（Collector / Raider）**：空手時依權重搶奪目標——未鎖定重型核心 > 中央黃金電池 > 領先隊伍回收爐內已解鎖的高分電池 > 標準電池。
4. **守門攔截手（Defender）**：當偵測到敵人帶著電池從自家回收爐方向逃離且距離 `< 4.5m` 時，優先追擊推搡將電池震落並就地回收。

## 7. 模組檔案結構與效能紅線

```text
mods/core-heist/
├── mod.json                 # id: "core-heist", requires: ["mpm-core", "team-party"]
├── main.gd                  # _mod_init / _mod_ready、註冊 admission 與場景替換
├── config.gd                # 平衡常數、顏色、階段時間、分數權重
├── official_minigame.gd     # 對接原版 Minigame 訊號介面
├── core_heist_game.gd       # 伺服器權威主邏輯、電池物件池、共振與計分
├── arena_meshes.gd          # 動態 2–4 隊場地、傳送帶、回收爐與柱體網格建構
├── ai_controller.gd         # lobby-bots 協作與抄家 AI
├── fx_pool.gd               # 基於 mpm-core.create_fx_pool() 的特效／火花／共振池
├── hud_ui.gd                # 敘事優先 HUD：左上無框比分、YOU 定位標、大號倒數與 CRT 共振條
├── team_support.gd          # 複製自 mods/_shared/team-support/team_support.gd
├── self_test.gd             # --self-test 無頭邏輯驗證
└── README.md                # 模組說明文件
```

### 效能與契約紅線（對齊[自研模組開發規範](mod-development.md)）
- **零執行期配置**：開局預建最多 **32 顆電池節點池**與共享材質／網格；所有火花、空投光柱、推搡衝擊與共振特效均透過 `mpm-core.create_fx_pool()` 預先配置並於開局倒數時在視錐內預熱。
- **熱路徑禁令**：`_process` / `_physics_process` 禁止呼叫 `get_property_list()`、禁止新建 `Mesh` / `StandardMaterial3D` 或 `queue_free()`。
- **無頭與Lint規範**：通過 `node scripts/mod-lint.mjs`、不可對 `call()` / `get()` / `get_meta()` 使用無型別 `:=`。

## 8. 開發里程碑與驗收清單

| 里程碑 | 交付項目 | 驗收標準 |
| --- | --- | --- |
| **M1：骨架與動態場地** | `mod.json`、`main.gd`、`config.gd`、`arena_meshes.gd`、註冊 `"team_only"` admission | 通過 `mpm-core` 准入檢查（FFA 鎖定、Team Party 2–4 隊正常顯示）；2/3/4 隊場地網格無重疊 |
| **M2：搬運、共振與金庫** | `core_heist_game.gd` 電池池、拾取／拋投、推搡震落、3 秒鎖定與雙人電磁共振 | 單機／無頭驗證 0–45–60–75 秒階段切換、雙人 `1.15×` 共振與 1 人隊 `0.85×` 保底 |
| **M3：連線同步、HUD 與 AI** | 20 Hz 快照同步、`hud_ui.gd`、`ai_controller.gd`、`fx_pool.gd` | 機器人能主動貼近持核隊友觸發共振並進敵區偷電池；60 FPS 壓測無節點洩漏 |
| **M4：測試、打包與實機驗收** | `self_test.gd`、沙盒測試、R2 封裝、[catalog/mods.json](../../../catalog/mods.json) 接入 | `SELF_TEST_PASSED`、`npm run check:architecture` 與 `npm test` 全數通過；Windows Steam 實機聯機驗證完成 |
